# Benchmarks

Generated by `python -m orchestrate_kit.bench` on Windows 11, Python 3.14.3. 5 repeats per command, cold subprocess each time (real Python startup cost included -- this is what a user actually waits for, not an in-process microbenchmark).

**Regenerate on your own machine:** `python -m orchestrate_kit.bench > BENCHMARKS.md`. These numbers are a property of this repository at this commit on THIS machine, not a universal claim.

## Reading these numbers

- **Every command is offline and makes no network call** — the numbers above are Python startup + local computation only, not affected by network latency or a provider's response time.
- **`selftest` is the slowest by design** — it builds a fixture repo, injects 13 defects one at a time, and runs the full evaluator against each. That's ~14 full evaluator passes in one command.
- **`evaluate .` is by far the slowest command, and that's expected**: the generic plugin's `fresh-clone` audit does a REAL `git clone` of this repository, then a fresh `python -m pytest` inside the clone (PLAYBOOK P15 — "the single highest-yield audit in this framework"). The number is dominated by that clone-and-test cost, not by anything specific to `orchestrate_kit`'s own logic, and it scales with the size of the repo being evaluated.
