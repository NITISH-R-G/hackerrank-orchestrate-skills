# Code of Conduct

This project runs on the same standard it asks of its content: **be direct,
be kind, cite your sources.**

## Expected

- Disagree with a claim, a design choice, or a rejected memory entry openly —
  that is how a rejection gets reconsidered, and the whole point of
  `reconsider_if` existing is that new evidence should change decisions.
- Back a factual correction with a source: an official HackerRank post, a
  reproducible benchmark, a link to the line of code in question.
- Assume good faith on a wrong number before assuming bad faith. This repo's
  own history includes multiple audits that were confidently, honestly wrong
  — see [TIMELINE.md](./TIMELINE.md).
- Keep technical criticism about the work, not the person who wrote it.

## Not acceptable

- Personal attacks, harassment, or discriminatory language or imagery, in
  issues, PRs, discussions, or commit messages.
- Submitting a claim, benchmark, or memory entry you know to be fabricated.
  This is treated as a correctness bug, not a style nit — see
  [CONTRIBUTING.md](./CONTRIBUTING.md#reporting-a-factual-error).
- Sustained disruption of discussions, or bad-faith reopening of settled
  issues without new evidence.

## Reporting

Open an issue, or if the matter is sensitive, contact the maintainer directly
through their GitHub profile. Reports are handled with discretion; retaliation
against a good-faith reporter is itself a violation.

## Enforcement

The maintainer may remove comments, close PRs, or block contributors who
violate this code of conduct. Enforcement decisions favor proportionality — a
first-time sharp comment gets a note, not a ban.
